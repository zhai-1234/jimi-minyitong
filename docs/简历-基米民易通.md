# 简历项目：基米民易通 · 社会救助政策 RAG 问答智能体

> 本文件只保留可直接写进简历的内容；项目原理、排查过程与面试问答见 [项目知识文档](项目知识文档.md)。

## 基本信息

- **项目名称**：基米民易通（社会救助政策智能问答）
- **角色**：独立完成（智能体工作流、知识库、评测、前端、可选后端）
- **时间**：2025.10 – 2025.11
- **形态**：Dify 1.9.1 工作流 + Vue 3 Web 前端 + Python 评测体系 + Spring Boot 日志服务（可选）

## 一句话介绍

基于 Dify 与自研 Vue 3 前端构建社会救助政策 RAG 问答智能体，用 50 题六类场景评测驱动检索、提示词与知识库迭代，最终关键要点召回 95.3%、来源命中 97.7%、超纲拒答 100%，平均响应 6.6 s。

## 技术栈

Dify 1.9.1（工作流 / 知识库 / 插件）· RAG（hybrid 检索、top_k、重排评估）· Vue 3 + Vite + Pinia + Element Plus · SSE 流式 · Python（标准库评测脚本）· Spring Boot 3.5 + MyBatis + MySQL · Docker Compose · GitHub Actions

## 项目内容（5 条，可直接使用）

- **设计并实现 50 题六类场景的 RAG 评测体系**（单政策 / 多政策 / 口语化 / 粤语 / 超纲 / 边界），仅依赖 Python 标准库，支持 mock 与真实调用双模式、基线对比报告；最终版本关键要点召回 **95.3%**、来源命中 **97.7%**、拒答正确率 **100%**，平均延迟 **6.6 s**、P95 **8.4 s**。
- **定位并修复引用来源丢失的两层根因**：Dify 迭代子图内事件不向上转发、LLM 上下文错误绑定字符串节点；重构为「查询拆解 → 单次融合检索 → 生成」后引用恢复，来源命中从不可用提升到 **72.1%**，再通过标注校准、原始问题检索、补充归纳文档与办理指南提升至 **97.7%**（+25.6 pt）。
- **将平均响应从 8.8 s 优化到 6.2 s（-30.2%）**：重写「问题分析」提示词（限定 3 个检索词、max_tokens=80）、回答约束 350 字、修复仅按英文逗号切分导致中文子问题退化的问题；P95 从 16.2 s 降至 9.4 s，答案长度从 932 字降到 376 字（-59.6%）。
- **完成知识库治理与 8 组以上检索对照实验**：把惠民清单中的医疗/教育/住房/就业条款整理成 6 份归纳文档并补充办理指南；对比 v1/v4 嵌入、重排策略与 top_k，识别中文 BM25 失效、超长文档挤占召回、重排服务不可用等问题并给出可落地的取舍。
- **实现前端与工程化闭环**：Vue 3 直连 Dify Service API，支持 SSE 流式与中断、会话管理、来源面板、引用角标联动、回答朗读（TTS 三级回退）、浏览器录音转 16 kHz WAV 的语音输入、按应用参数校验的文件上传；配套 Spring Boot 问答日志服务（6 个单测通过）、Dify 补丁脚本化与 compose 挂载、GitHub Actions 构建/测试与 Pages 在线演示。

## 精简版（3 条，适合篇幅有限）

- 基于 Dify + Vue 3 搭建社会救助 RAG 问答系统，设计 50 题六类场景评测，最终要点召回 **95.3%**、来源命中 **97.7%**、拒答 **100%**、平均 **6.6 s**。
- 定位 Dify 引用不转发与上下文绑定错误，重构检索链路使来源指标恢复，并通过标注修正与知识库补充把来源命中从 **72.1% 提升到 97.7%**。
- 通过提示词重写、答案精简与子问题切分修复，将平均延迟降低 **30.2%**（8.8 s → 6.2 s），并实现流式对话、朗读、语音输入、文件上传等前端能力。

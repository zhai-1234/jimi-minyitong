# 项目说明 · 基米民易通

本文记录项目定位、组成与关键工程决策，运行方式见根目录 [README.md](../README.md)，评测细节见 [evaluation/README.md](../evaluation/README.md)。

## 1. 项目要解决的问题

社会救助政策分散在省市文件、区级惠民清单和镇街办事指南里，困难群众常见的提问是口语化甚至粤语的（「低保咋弄啊」「湿湿碎点算」）。项目用 RAG 智能体把「条件、材料、流程、渠道」答准，并且必须能指出依据的是哪份文件。

## 2. 组成

- **智能体**：Dify 1.9.1 advanced-chat 工作流，知识库 25 份原始文档 + 6 份惠民清单归纳文档 + 1 份办理指南，嵌入 `text-embedding-v1`，hybrid 检索 top_k=4。
- **前端**：Vue 3 单页应用，直连 Dify Service API，负责流式对话、来源展示、朗读、语音输入、文件上传与反馈。
- **后端（可选）**：Spring Boot 问答日志服务，默认关闭。
- **评测**：50 题六类场景，Python 标准库实现，输出 CSV / JSON / Markdown 报告。

## 3. 关键决策记录

| 决策 | 结论 | 原因 |
| --- | --- | --- |
| 前端形态 | 自研 Vue 3 页面，不再 iframe 嵌入 Dify | 可定制来源面板、朗读、语音、上传；避免 iframe 样式与鉴权限制 |
| 检索位置 | 知识检索移出迭代节点 | Dify 不转发迭代内 `retriever_resources`，移出后引用才可用 |
| 查询策略 | 普通提问用原始问题检索；带文件时用「原问题+子问题」融合查询 | 融合查询语义稀释，原始问题命中更高（A/B：82.3% vs 70.6%） |
| 重排 | 关闭 | gte-rerank 返回空、bce 对长分块 400；多组实验收益不稳定 |
| 嵌入模型 | 保持 v1，不升级 v4 | v4 召回更高但来源命中下降，综合后 v1+归纳文档最优 |
| 超大手册 | 保留启用 | 停用对子集指标无显著变化，且流浪救助题依赖它 |
| 回答长度 | ≤350 字、结构化 | 延迟下降 30%，引用更聚焦 |
| 后端 | 保留最小后端，默认关闭上报 | 见 [架构决策](架构决策-是否需要后端.md) |

## 4. 迭代时间线（2026-11）

1. 基线评测：要点召回 93.4%，来源指标不可用，平均 8.8 s。
2. 延迟优化：提示词重写、回答精简、子问题切分修复，-30.2%。
3. 引用修复：检索移出迭代 + LLM 上下文接检索数组，来源命中恢复为 72.1%。
4. 来源优化：标注修正、原始问题检索、top_k 调整，90.7%。
5. 嵌入实验与知识库补充：归纳文档、办理指南，最终 97.7%。
6. 前端能力补齐与目录整理：朗读、语音输入、文件上传、引用角标、建议问题修复。

## 5. 已知限制

- 关键词匹配是代理指标，评测存在 ±2~4 个百分点波动。
- 中文 BM25 实际未生效，hybrid 主要由向量贡献。
- Dify 容器内补丁不持久，重建后需重新应用。
- 平台默认模型（会话命名/建议问题/STT）曾在数据库中被配置为不可用模型，已修正，迁移到新环境时需检查。
